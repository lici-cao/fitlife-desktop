# P1 改造说明（唯一约束与索引 · 幂等键 · RBAC 与归属 · 密钥外置 · 统一响应体）

> 对应《系统优化方案设计》第八节 P1 阶段（2 周 / 10 人日）。
> 本文档面向三件事：**改了什么、为什么这么改、怎么验证与回滚**。
> 全部改动向后兼容：老前端不改也能跑，新前端能拿到 4xx 语义与幂等能力。

## 0. 一页纸结论

| 项 | 改造前 | 改造后 | 验收方式 |
|---|---|---|---|
| 唯一约束 | 当日记录无唯一键，重复提交可写两条 | `uk_daily_user_date(user_id,date)` + 明细表联合索引 | `information_schema` 断言 |
| 幂等键 | 双击/重试→重复热量累计 | `Idempotency-Key` + 唯一键 + 切面回放；异体 409 | 同 key 两次提交，第二次 `Idempotent-Replay: true` |
| 权限 | 所有 token 权限恒为空，`/api/ai/**` 匿名可调 | JWT 装 `ROLE_*`，默认 `authenticated()`，`/api/admin/**` 仅 ADMIN | 未登录 401 / 普通用户 403 / 管理员 200 |
| 归属 | 各 Controller 自行判 userId，漏判即越权 | `@OwnershipCheck` 切面在执行前 `existsByIdAndUserId` 判定并写审计 | 访问他人计划 → 403 且 `audit_log` 有记录 |
| 密钥 | JWT secret、DB 口令、GLM Key 明文入仓 | 全部 `${ENV:}`，本地默认值独立到 `application-local.yml` | 源文件无明文；缺 secret 启动即失败 |
| 响应体 | 控制器 `catch` 后回传 `e.getMessage()` | 全局异常处理 + `BusinessException`，500 只给追踪号 | 任意失败响应均为 `{code,success,message,data}` |

## 1. 唯一约束与索引

### 1.1 改动范围

- `sql/migration/V1__p1_hardening.sql`（新增，可重复执行）
- `fitlife-mysql.sql`（新装即带约束，老库靠迁移补齐）
- 实体：`entity/DailyRecord` 不改字段，约束由数据库保证

### 1.2 实现方式

1. **先去重再加唯一键**：迁移脚本先按 `(user_id, date)` 保留 `id` 最小的一条，再 `ADD UNIQUE`；否则老库存在重复行时 DDL 会直接失败。
2. **幂等 DDL**：MySQL 5.7/8 没有 `ADD COLUMN IF NOT EXISTS`，统一用 `information_schema` 查一次 + `PREPARE/EXECUTE`，重复执行不报错。
3. **索引补齐**：`food_intakes`、`workout_records` 加 `(user_id, date)`；`plans` 加 `(user_id, created_at)`，覆盖「我的计划列表」排序。
4. `users` 增加 `role`、`status`、`last_login_at` 与 `idx_users_role`，为第 3 项提供存储。

### 1.3 验收标准

- `uk_daily_user_date` 存在且 `non_unique = 0`；
- `idx_food_user_date`、`idx_workout_user_date` 存在；
- 对同一用户同一天并发 `POST /api/data/food-intake` 两次，`daily_records` 仍只有一行。

### 1.4 回滚

```sql
DROP INDEX uk_daily_user_date ON daily_records;
DROP INDEX idx_food_user_date ON food_intakes;
DROP INDEX idx_workout_user_date ON workout_records;
ALTER TABLE users DROP COLUMN last_login_at, DROP COLUMN status, DROP COLUMN role;
```

## 2. 幂等键

### 2.1 改动范围

| 文件 | 作用 |
|---|---|
| `entity/IdempotencyRecord.java` | 幂等记录（`status=0` 处理中 / `1` 已完成） |
| `repository/IdempotencyRecordRepository.java` | JPA 映射（供 ddl-auto 兜底建表） |
| `service/IdempotencyService.java` | **JdbcTemplate** 实现 claim/find/markDone/release |
| `aspect/IdempotencyAspect.java` | 切面：认领 → 执行 → 落盘 / 释放 |
| `common/annotation/Idempotent.java` | 标记注解（`ttlSeconds`、`staleSeconds`、`required`） |
| `controller/PlanController`、`DataController` | `generate`、`chat`、`food-intake`、`exercise-burn`、`custom-foods` 加 `@Idempotent` |
| `FitLife-web/src/utils/http.ts` | 自动生成并携带 `Idempotency-Key` |

### 2.2 实现方式

- **键**：`(user_id, idem_key)` 唯一。请求头 `Idempotency-Key`，长度 ≤ 128。
- **时序**：切面先把键写进表（`status=0`）→ 执行业务 → 成功且 `code<400` 时把响应体 JSON 落盘（`status=1`）→ 失败或抛异常则删除记录，允许同 key 重试。
- **回放**：再次收到同 key、同请求体哈希时，不再执行，直接返回上次响应体，并加 `Idempotent-Replay: true`。
- **冲突**：同 key 但请求体哈希不同 → `409`；仍在处理中且未超过 `staleSeconds` → `409`；超过 `staleSeconds` 视为进程崩溃残留，删除后重新认领。
- **为什么用 JdbcTemplate 而不是 JPA**：`saveAndFlush` 撞唯一键会让 Hibernate persistence context 进入不可用状态（`don't flush the Session after an exception occurs`），而「撞键」恰恰是幂等的正常分支。JDBC 插入失败只影响该语句。
- **降级**：幂等表不可用（表未建、库抖动）时记 `WARN` 并放行，不阻断业务。

### 2.3 验收标准

1. 同 key + 同 body 连续两次 `POST /api/data/food-intake`：两次都 200，第二次响应头含 `Idempotent-Replay: true`，响应体逐字节一致；
2. 同 key + 不同 body：`409`，且提示「同一个 Idempotency-Key 不能用于不同的请求内容」；
3. 当日 `food_intake` 只增加一次。

### 2.4 回滚

- 前端：`http.ts` 移除自动加键逻辑（或请求设 `skipIdempotency: true`）；
- 后端：删除控制器上的 `@Idempotent` 即可停用，表可保留无害。

## 3. RBAC 与归属切面

### 3.1 改动范围

| 文件 | 作用 |
|---|---|
| `entity/User.java` | `role`（USER/ADMIN）、`status`（ACTIVE/DISABLED）、`lastLoginAt` |
| `service/JwtService.java` | token 增加 `role` claim；启动校验 secret |
| `filter/JwtAuthenticationFilter.java` | 按 role 装载 `ROLE_*`；禁用账号 403；统一 401 JSON |
| `config/SecurityConfig.java` | `@EnableMethodSecurity`；默认 `authenticated()`；`/api/admin/**` 需 ADMIN |
| `common/annotation/OwnershipCheck.java` + `aspect/OwnershipAspect.java` | 水平越权防护 |
| `controller/AdminController.java` | `/api/admin/users`、`/api/admin/audit-logs`、改状态/角色 |
| `entity/AuditLog.java` + `service/AuditLogService.java` | 审计（只记动作与资源，不记业务正文） |

### 3.2 实现方式

- **认证**：JWT 校验通过后查用户，`status=DISABLED` 直接 403；权限集合由 `role` 生成，取代原来的 `Collections.emptyList()`。
- **授权**：默认所有接口需登录（原 `anyRequest().permitAll()` 是最大的口子）；`/api/auth/**`、`/api/health`、GET `/api/exercise/**` 公开；`/api/admin/**` 需 `ROLE_ADMIN`。
- **归属**：`@OwnershipCheck(type=PLAN, idParam="id")` 在执行前用一条 `existsByIdAndUserId` 判定，越权 403 并写 `audit_log`（`action=PLAN_ACCESS_DENIED`）。需要 `-parameters` 编译参数，已在 `pom.xml` 打开。
- **首管理员**：`dandan` 在迁移脚本中被置为 `ADMIN`；新装库在建库脚本里直接是 ADMIN。

### 3.3 验收标准

- 无 token 访问 `/api/plan/current` → `401`；
- 普通用户 token 访问 `/api/admin/users` → `403`；
- `dandan/123456` → `200` 且返回分页结构；
- 用户 A 用 `GET /api/plan/{B的计划id}` → `403`，`audit_log` 新增一条 `PLAN_ACCESS_DENIED`。

### 3.4 回滚

把 `SecurityConfig` 的 `anyRequest().authenticated()` 改回 `permitAll()` 可快速恢复旧行为（不建议）；角色列可保留，不影响旧逻辑。

## 4. 密钥外置

### 4.1 改动范围

- `FitLife-java/src/main/resources/application.yml`：`jwt.secret: ${JWT_SECRET:}`、`DB_PASS`、`ZHIPU_API_KEY` 等全部改为环境变量，删除明文兜底；
- `application-local.yml`（新增）：仅本地开发的默认值（`spring.profiles.default: local`）；
- `service/JwtService.java`：`@PostConstruct` 校验 secret 非空且 ≥32 字节，否则启动失败；
- `start-fitlife.ps1` / `scripts/p1-oneclick.ps1`：读取或生成 `.env`，启动子进程时注入；
- `.env`（生成物，已加入 `.gitignore`）。

### 4.2 实现方式

- 环境变量优先级最高；`.env` 只作为本地便捷方式，**不进仓库**。
- 缺失 `JWT_SECRET` 时一键脚本用 `RandomNumberGenerator` 生成 48 字节 Base64，写入 `.env` 并注入进程。
- `application-local.yml` 里保留一组仅用于本地联调的固定 secret，并在文件头注明「不要用于部署」。
- **坑**：Spring Boot 对多个配置源里的同一个 list 是**整体替换**而不是按下标合并，所以在 `application-local.yml` 里重写 `ai.providers` 会让未写出的字段变 `null`；因此本地演示 Key 只通过 `.env` 注入。

### 4.3 验收标准

- `application.yml` 中检索不到 `fitlife-secret-key-at-least-256-bits` 与 `aeb430a5…`；
- 不设 `JWT_SECRET` 启动 → 抛 `IllegalStateException` 并给出中文提示；
- 设置 32 字节以上随机串 → 正常启动，登录签发/校验 token 正常。

### 4.4 回滚

把 `application.yml` 里的 `${JWT_SECRET:}` 改回字面量（不推荐，会重新暴露），或提供 `SPRING_PROFILES_ACTIVE=local` 走本地默认值。

## 5. 统一响应体

### 5.1 改动范围

| 文件 | 作用 |
|---|---|
| `dto/ApiResponse.java` | 保留 `code/success/message/data`，`success` 由构造器按 `code<400` 推导 |
| `controller/GlobalExceptionHandler.java` | 14 类异常统一翻译；500 只回追踪号 |
| `common/BusinessException.java` | 业务失败的标准异常（带 code/data） |
| 各 Controller | 删除 `try/catch RuntimeException → badRequest(e.getMessage())` |
| `service/AiService.java` | 限流 → `BusinessException(429)`；依赖不可用 → `503` |

### 5.2 实现方式

- **成功**：`ResponseEntity.ok(ApiResponse.success(data))`，`code=200`。
- **失败**：抛 `BusinessException(code, msg)`，全局处理器输出对应 HTTP 状态码 + 同构 JSON。
- **500**：日志里带完整堆栈和 12 位追踪号，响应体只给「服务器内部错误，请稍后重试（追踪号 xxx）」。
- **不泄露**：不再把 `e.getMessage()`、上游厂商错误、SQL 片段回传前端；`LlmGateway.LlmException` 统一 503 文案。
- **兼容**：`success(String)`、`success(String,Object)`、`success(Object)`、`error(String)`、`error(String,Object)`、`serverError(String)` 签名保留，老代码零改动。

### 5.3 验收标准

- 任意失败响应均含 `code/success/message/data` 四字段，且 `success == (code < 400)`；
- 未登录：`401`；越权：`403`；重复提交冲突：`409`；限流：`429`；大模型不可用：`503`；
- 500 响应体不含异常类名、SQL、供应商原文。

### 5.4 回滚

前端若依赖旧文案，可在 `GlobalExceptionHandler` 中把对应处理器的 message 改回；结构不建议回退（前端按 `code` 判断的页面本来就能工作）。

## 7. 兼容性与已知限制

1. **老前端**：不带 `Idempotency-Key` 时 `@Idempotent` 默认放行（`required=false`），行为与改造前一致。
2. **登录页**：`http.ts` 对 `/auth/` 路径的 401 不再清 token 跳转，避免「密码输错一次就整页刷新」。
3. **403 不再登出**：登录了但没权限的用户留在原页面看提示，而不是被踢回登录页。
4. **审计表增长**：`audit_log` 目前只记越权与管理员操作，量很小；后续如需长期保留，按 `created_at` 归档。
5. **幂等记录清理**：`idempotency_key` 目前不自动清理；P4 可加定时任务删除 `created_at` 超过 7 天的记录。
6. **未做**：登录失败锁定、refresh token、Redis 分布式限流——属于 P2/P3 范围，本次不引入新中间件。
7. **脚本编码**：`.ps1` 必须保存为 **UTF-8 带 BOM**。Windows PowerShell 5.1 会按 GBK 解析无 BOM 的文件，中文注释会导致「字符串缺少终止符」。
8. **既有的实体/SQL 类型不一致（非本次引入）**：`exercises.difficulty` 建表为 `TINYINT`，实体声明为 `Integer`，因此 `ddl-auto=validate` 会启动失败。本次沿用原有 `ddl-auto` 设置，未擅自改字段类型；建议后续统一为 `TINYINT` + 实体 `Byte`/`Short`，或在建表脚本里改成 `INT`。

### 修复的两处历史编译错误

原仓库在本次之前**从未真正编译过**，`mvn compile` 直接报错，已一并修复：

### 自检覆盖的关键行为

- 未登录访问 `/api/plan/current` → **401**，响应体为统一四字段 JSON；
- 普通用户访问 `/api/admin/users` → **403**「没有权限执行该操作」；
- 管理员访问 `/api/admin/users` → **200**，返回分页 `rows/total/page/size`；
- 同 `Idempotency-Key` 同请求体重复提交 → 两次 **200**，第二次带 `Idempotent-Replay: true`，响应体与首次字节一致；
- 同 `Idempotency-Key` 不同请求体 → **409**；
- 越权删除他人自定义食物 → **403**，并在 `audit_log` 落一条 `CUSTOM_FOOD_ACCESS_DENIED`；
- 停用账号登录 → **403**；管理员改状态/角色生效；禁止改自己 → **400**。
